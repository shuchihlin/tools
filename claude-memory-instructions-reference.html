CLAUDE MEMORY & INSTRUCTIONS

Reference Notes — How Claude Knows What It Knows About You
Last updated: June 26, 2026

// THE TWO SEPARATE SYSTEMS

INSTRUCTIONS FOR CLAUDE

Explicit rules and preferences you type into a settings field. Claude reads these at the start of every session.

  • Manually written by you
  • Persistent across sessions
  • Revealed by: "what are my instructions?"
CLAUDE'S MEMORY

Facts Claude inferred and saved from past conversations — without you explicitly writing them down.

  • Auto-generated from chat history
  • Persistent across sessions
  • Revealed by: "what do you know about me?"
⚠ KEY DISTINCTION

These two systems are independent. Asking "what are my instructions?" does NOT reveal memory, and "what do you know about me?" does NOT reveal instructions. You need both queries to get the full picture of what Claude carries into a session.

// WHERE TO FIND AND EDIT EACH

INSTRUCTIONS FOR CLAUDE — LOCATION

Claude Desktop:
Settings → General → Instructions for Claude

Claude.ai (web):
https://claude.ai → Settings → General → Instructions for Claude

Both surfaces show the same field — it syncs with your cloud account. Edit directly in the text box and save.

CLAUDE'S MEMORY — LOCATION

Claude.ai (web):
https://claude.ai → Settings → Privacy → Memory

You can view all stored memory entries, edit individual facts, or delete them. Claude Desktop does not expose a memory management UI — use the web interface.

// WHAT DOES NOT WORK FOR PERSISTENT INSTRUCTIONS

LOCAL CLAUDE.MD FILES

It is tempting to edit markdown files on disk to set persistent preferences. The results are inconsistent:

  • C:\Users\master\.claude\CLAUDE.md — read by Claude Code CLI only, not by Cowork
  • C:\Users\master\Claude\.claude\CLAUDE.md — does not exist by default
  • Session-specific CLAUDE.md paths shown in system context — these are virtual references; the files do not exist on disk

For Cowork, use the Settings UI, not local files.

// WHY CLAUDE'S WEB FETCH CAN DIFFER FROM YOUR BROWSER

REMOTE SANDBOX, NOT YOUR PC

When Claude fetches a URL, the request originates from a remote Linux sandbox in a cloud data center — not from your local machine. This means:

  • Different geographic location → different CDN edge node
  • Different cache state → may serve stale content your browser has already refreshed
  • Not a bug — expected behavior given the architecture

If Claude reports outdated content for a URL you can see is current in your browser, this is the reason.
