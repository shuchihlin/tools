Part 1 / Kimi K3 (Moonshot AI)

Model evaluation

Key facts

  • Released 2026-07-16 (API); open weights released 2026-07-27
  • 2.8T parameters, Mixture-of-Experts: 896 experts, 16 active per token (~4% utilization per forward pass)
  • 1M-token context window; native text / image / video input
  • Largest open-weight model to date; weights ship as 96 safetensors shards, ~1.56 TB total
  • Native MXFP4 (4-bit) weights via quantization-aware training — 4-bit is its native precision, no post-hoc compression loss

Pricing

  • $3 / $15 per million input / output tokens; cached input $0.30
  • Claude Sonnet-tier pricing; most expensive Chinese-lab model to date (predecessor K2.6: $0.95 / $4)

Verdict
First open-weight model within ~3 points of the closed frontier. But the price advantage is thin, self-hosting needs a multi-GPU cluster (impractical for individuals), and most agentic wins remain vendor-reported. Best fit: inference providers, enterprises needing open weights, data sovereignty, or 1M context.

On the evaluator: Artificial Analysis (artificialanalysis.ai) is an independent commercial benchmarking firm. Vendor-neutral and widely cited, but not a standards body — the best available independent signal, not an audit.

The core equation

y = W·x + b
W, b — weights / parameters: the learned numbers baked into the model file. Identical for every request. This is the 1.56 TB.
x — input / activation: the transient signal flowing through (your prompt as vectors, then each layer's output). Never stored in the model.
y — output, which becomes the next layer's x.
Adaptive-filter analogy: W = converged coefficients, x = input signal. Nobody calls the signal a parameter of the filter.

Core vocabulary

  • Parameter = weight (interchangeable in practice). Each is one learnable number. "2.8T parameters" counts everything gradient descent adjusts: W matrices, biases, embeddings, norm scales — all shipped in the release. Biases are ~4 orders of magnitude fewer than W per layer; many modern architectures omit them entirely.
  • Corpus (語料庫): trillions of tokens of training text — the "signal source" that drove weight convergence. Weights ≈ lossy compression of corpus regularities; hallucination = compression artifact. Data quality & mix often matter more than architecture — the top trade secret.
  • File size formula: size ≈ params × bits ÷ 8. K3: 2.8T × 4 ÷ 8 = 1.4 TB + scaling factors ≈ 1.56 TB. Works in reverse: file size ÷ param count reveals any model's quantization precision.

Architecture vs weights

  • Architecture (code) dictates what operations run: matmul, attention, MoE routing. Generic; contains zero knowledge. K3's and GPT's are structurally similar.
  • Weights dictate what those operations compute: all knowledge, capability, "personality." Same code + different weights = different product — exactly what fine-tuning produces.
  • Behavior ≠ logic. No rules exist anywhere inside. Weights encode statistical dispositions; apparent reasoning is emergent from billions of multiply-adds. Consequences: no patching, no determinism guarantees, interpretability unsolved.

The three codebases of an LLM

#CodebaseReleased?Contents
1 Inference / architecture Released Few thousand lines of PyTorch: layers, attention, routing, config, tokenizer. Required to make weights usable.
2 Training Closed Distributed orchestration, RL/RLHF infrastructure, hyperparameter schedules. The factory.
3 Data pipeline Closed Crawling, dedup, filtering, corpus mixing. Arguably the most valuable secret.

Open weights vs open source

  • Open weights = weights + inference code + tokenizer + technical report. Like shipping a compiled binary plus the runtime spec.
  • Open source (OSI-strict) = all three codebases + data + unrestricted license. Like shipping the full buildable source tree. Rare (e.g., AI2 OLMo).
  • Most "open source" headlines (Llama, DeepSeek, Kimi) are actually open weights with custom licenses. K3's license includes a revenue gate on large commercial resellers — not MIT/Apache.

Why downloaders can operate without training code

Inference never references training. The weights are a finished product — all value produced by codebases #2 and #3 is already baked into the numbers. Running = load weights → execute the architecture's matrix operations.

FILTER
To operate a converged adaptive filter you need coefficients + structure — not the adaptation algorithm.
SOFTWARE
To run a binary you need a runtime — not the compiler or build system.
HARDWARE
To use a chip you need the datasheet — not the fab.

Fine-tuning still works because open frameworks (PyTorch, HuggingFace PEFT) provide a generic training capability — a substitute compiler — good enough for incremental adjustment, not for trillion-token industrial pretraining.
